# AI vs Human Text Classification (NLP Project)

## Project Overview
This project aims to classify whether a given text was written by a human or generated by an artificial intelligence model using machine learning techniques. It was developed for the BIM432 Natural Language Processing course at Istanbul Sabahattin Zaim University.

## Dataset
- **Main Dataset:** The training and evaluation pipeline uses `data/AI_Human.csv`.
- **Balanced Sample:** A smaller balanced sample, `data/dataset_sample.csv`, is included for quick inspection and lightweight exploration. It contains 100 human-written and 100 AI-generated texts.
- **Source:** Kaggle AI vs Human Text Dataset.

## Methodology

**1. Preprocessing**
- Converting text to lowercase
- Removing punctuation
- Tokenizing text with NLTK `word_tokenize`
- Removing English stopwords with NLTK

**2. Feature Extraction**
- TF-IDF (Term Frequency-Inverse Document Frequency) was used to convert text into numerical features.
- The feature space was limited to the 5,000 most informative features.
- Unigram and bigram features were included using `ngram_range=(1, 2)`, allowing the model to capture both single-word and two-word patterns.

**3. Models**
- Logistic Regression as a baseline model
- Support Vector Machine using LinearSVC

**4. Train/Test Split**
- Both models are evaluated on the same train/test split.
- The `split_data()` function uses `stratify=y` to preserve class proportions in the split.

**5. Cross-Validation**
- A 5-Fold Stratified Cross-Validation step was added to support overfitting analysis.
- Cross-validation outputs are saved as `results/figures/cross_validation.png` and `results/figures/cross_validation.txt`.

## Key Insights
- **Model Performance:** SVM performed slightly better than Logistic Regression on the TF-IDF feature representation.
- **AI-Writing Patterns:** AI-generated texts in the dataset often show more formal and template-like wording, including terms such as "additionally" and "conclusion".
- **Human-Writing Patterns:** Human-written texts tend to contain more variation and less rigid phrasing, including words such as "almost" and "would".

## Error Analysis
Incorrect predictions are analyzed automatically with the `perform_error_analysis()` function.

- **False Positives:** Some human-written texts with formal or template-like structure may be classified as AI-generated.
- **False Negatives:** Some AI-generated texts with informal, personal, or less structured wording may be classified as human-written.

Detailed error analysis files:
- `results/error_analysis_lr.txt`
- `results/error_analysis_svm.txt`

## Saved Model and Prediction Script
When the pipeline is executed, the best-performing SVM model and the TF-IDF vectorizer are saved to disk:

- `results/svm_model.joblib`
- `results/tfidf_vectorizer.joblib`

The saved model can be used for new text predictions through `src/predict.py`.

## How to Run the Project

1. **Install requirements:**
```bash
pip install -r requirements.txt
```

2. **Run the full training and evaluation pipeline:**
```bash
python -m src.run
```

This command:
- Loads the dataset and prints the class distribution
- Applies text preprocessing
- Extracts unigram and bigram TF-IDF features
- Splits the dataset using stratified train/test splitting
- Trains and evaluates Logistic Regression and SVM on the same test set
- Generates confusion matrices, feature importance plots, model comparison plots, and cross-validation outputs
- Creates error analysis reports
- Saves the SVM model and TF-IDF vectorizer under `results/`

3. **Run prediction on new text:**
```bash
python -m src.predict
```

If saved model files already exist, the script loads them directly. Otherwise, it trains and saves a new model.

## Limitations
Although the SVM model achieved 99.77% accuracy on this dataset, the results should be interpreted within the scope of the dataset and experimental setup.

- **Dataset Dependence:** The high accuracy may be related to writing patterns present in the Kaggle dataset. Performance should be re-evaluated on texts from different sources.
- **Style-Based Detection:** The model focuses mainly on lexical and stylistic patterns rather than deeper semantic understanding.
- **Future Language Models:** Newer language models may produce texts with different stylistic patterns, which can affect detection performance.
